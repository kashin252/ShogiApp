# 実装計画：コード品質改善およびAI（探索・評価）の強化

先のコード品質点検（Code Quality Audit）で判明したアーキテクチャ上の課題を解決し、さらにRustエンジンの探索効率および評価関数を強化することで、より滑らかで強い将棋アプリを実現します。

## 1. ネイティブ連携層 (JNI / Kotlin) の非同期化
- **対象**: `ShogiEngineModule.kt`
- **目的**: 探索中のUIフリーズ解消
- **内容**: `searchBestMove` メソッドが現在React Nativeのネイティブモジュールスレッドを専有しているため、Kotlinの `CoroutineScope(Dispatchers.Default)` を用いて非同期実行化します。これにより、AI思考中もUIスレッドがブロックされず、「待った」や「投了」などの操作が直ちに反応するようになります。

## 2. フロントエンド層 (React Native) のUX・レンダリング最適化
- **対象**: `GameScreen.tsx`, `Board.tsx`, `CapturedPieces.tsx`
- **目的**: 持ち駒操作の不具合解消、および不要な再描画の防止によるパフォーマンス向上
- **内容**:
  - **持ち駒キャンセルの実装**: 現在、持ち駒（手駒）をタップして選択状態(`selectedSquare`)にした後、キャンセルする手段が不足しています。盤外のタップや同じ駒の再タップで `setSelectedSquare(null)` となるよう、イベントハンドラを修正します。
  - **レンダリングの最適化**: `GameScreen.tsx` に集中しているロジック（タイマー処理、ゲーム状態管理）をカスタムフックへ分離。
  - `Board.tsx` や `CapturedPieces.tsx` などの末端コンポーネントに `React.memo` を適用し、Propsが変化しない限りレンダリングをスキップさせます。

## 3. Rust Engine 探索効率の向上
- **対象**: `search.rs`
- **目的**: 同じ思考時間内でより深いDepthまで探索させる
- **内容**:
  - **Null Move Pruning (NMP)**: 相手のターンをスキップ（Null Move）してもなお評価値が高い場合、その枝の探索を打ち切る手法。既に基本機能があるか確認し、改良します。
  - **Killer Heuristic**: 直前の探索でβカットを引き起こした「強い指し手（Killer Move）」を記憶しておき、次のノードで優先して探索することで、Alpha-Betaのカット効率を劇的に向上させます。

## 4. Rust Engine 評価関数の強化
- **対象**: `evaluate.rs`, `pst.rs`
- **目的**: AIの大局観（駒の形の良さや玉の堅さ）の向上
- **内容**:
  - 単純な駒割り（Material）と位置（PST）による評価に加え、**モビリティ（Mobility: 駒の利き数の多さ）** を評価に加味します。
  - 特に、玉の周辺に金銀が密集しているか（King Safety）のような簡単な囲いの評価を追加し、守備の堅さを重視させます。
